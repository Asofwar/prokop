## Исправления по мотивам других форков

Пять ошибок, найденных при сравнении с другими форками (Screamshow, slayer326, Tachyon, netshift), и новая строка в диагностике. Обновление ставится поверх, настройки не меняются, ничего делать вручную не нужно.

## Что изменилось

- **Подписки не теряют кэш после обновления.** Автоматический User-Agent подписки содержит версию Prokop и sing-box. После каждого обновления сохранённый кэш считался устаревшим и удалялся ещё до новой загрузки. Если загрузка не удавалась, секция оставалась без серверов. Теперь кэш, скачанный с автоматическим профилем прошлой версии, остаётся рабочим до следующего обновления подписки. Заданный вручную User-Agent по-прежнему должен совпадать точно.
- **Перезапуск больше не отдаёт DNS обычным серверам.** Кнопка «Перезапуск», `prokop restart` и `/etc/init.d/prokop restart` между остановкой и запуском возвращали dnsmasq к обычным DNS-серверам. Устройства успевали получить и закэшировать настоящие IP и до истечения TTL ходили мимо FakeIP. Теперь перезапуск работающего Prokop — один переход, как при перезагрузке конфигурации: dnsmasq продолжает отправлять запросы в sing-box, пока тот перезапускается. Если перезапуск не удался, DNS возвращается обычным серверам, как раньше. Если Prokop остановлен или перезапуск идёт из скрипта пакета при обновлении, перезапуск, как и раньше, останавливает и запускает Prokop.
- **Смена источников списков после сорванного применения.** Если применение скачанных списков однажды не удалось, каждая следующая перезагрузка конфигурации пыталась применить их снова. Когда после этого менялись источники списков, все перезагрузки обрывались с ошибкой «Active list generation could not be restored» до следующего обновления списков. Теперь повтор идёт только пока скачанные списки соответствуют текущим источникам, иначе перезагрузка идёт как обычно и запускает обновление списков.
- **«Исключить NTP» действует и на сам роутер.** Раньше настройка выводила из туннеля только NTP-запросы устройств. Синхронизация времени самого роутера могла попасть в sing-box, если NTP-сервер оказывался в подсетях секции.
- **Панель проверяет задержку каждого узла в группе «Приоритет».** Раньше проверялась только сама группа, то есть узел, который она использует сейчас, а у остальных узлов задержки не было.
- **Новая строка в диагностике «Окружение»: «Открытые файлы sing-box».** Показывает, сколько файлов и соединений открыто у работающего sing-box и какой у него предел. С 80% предела строка становится предупреждением: когда предел достигнут, новые соединения через sing-box не открываются. sing-box, установленный пакетом, работает с пределом из init-скрипта пакета, а там он не задан (часто 4096). У ядра, которое ставит сам Prokop, предел поднят.

## Известная проблема ядра sing-box-extended

В sing-box-extended 2.7.2 (ядро по умолчанию) UDP с доменным адресом не проходит через группы selector и urltest, а Prokop отправляет трафик секций именно через selector. Под это попадает QUIC (HTTP/3) к доменам из списков прокси-секций; браузеры в этом случае переходят на TCP. В основном sing-box ошибку исправили в 1.14.2, в extended исправления пока нет. Prokop это не меняет: исправление нужно в самом ядре. Вариант ядра «stable» (пакет OpenWrt 1.13) этой ошибки не имеет.
