## Первый запуск со списками через прокси

Этот выпуск исправляет последнюю ошибку из обзора форков Forkop (A9). Обновление ставится поверх, ничего делать вручную не нужно.

## Что исправлено

- **Prokop не запускался без кэша списков, если списки качаются через прокси (A9).** При включённой настройке «Скачивать списки через прокси» Prokop перед стартом маршрутизации скачивает списки доменов и IP через прокси выбранного правила. Этот прокси работает внутри sing-box, а sing-box запускается только после списков. Если кэша списков на роутере ещё не было (новая установка, сброс, потерянный кэш), загрузка не удавалась, и запуск прерывался. Так повторялось при каждом запуске, пока настройку не выключали вручную. Теперь запуск поднимает временный sing-box, который обслуживает только этот прокси. Списки скачиваются через выбранное правило, как и настроено, без прямых запросов. Затем временный sing-box останавливается, и Prokop запускается как обычно. Если старт прервался, пока временный sing-box работал, следующий запуск сначала остановит его.

## Что проверено

- PASS: автоматические тесты, от root и в окружении как в CI (без root, без `uci`). Новый тест падает на старом коде.
- PASS: на настоящем sing-box 1.12.0, 1.12.9 и sing-box-extended 1.5.0, 2.3.2, 2.7.1 и 2.7.2. Временный sing-box запускается, настоящее обновление списков скачивает список с локального сервера через исходящее подключение правила и сохраняет кэш. Затем временный sing-box останавливается. Без него та же загрузка не удаётся.
- NOT TESTED: на роутере. Не проверялся первый запуск с настоящим VPN-сервером и подпиской.
- Ограничение: если у правила, через которое качаются списки, при запуске ещё нет ни одного узла (например, его подписка не скачалась и кэша подписки нет), списки скачать не через что, и запуск остановится с ошибкой в журнале.
