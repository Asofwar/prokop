## Исправления из форков

Этот выпуск переносит в Prokop шесть исправлений, найденных в форках Forkop: три ошибки и три улучшения для роутеров с малым объёмом памяти и медленной флеш-памятью. Обновление ставится поверх, ничего делать вручную не нужно.

## Что изменилось

- **URLTest с редкой проверкой (A2).** У группы URLTest с интервалом проверки больше 30 минут sing-box не запускался: он требует, чтобы `idle_timeout` был не меньше интервала, а по умолчанию это 30 минут. Раньше Prokop исправлял это только для старой группы с именем `urltest`. Теперь любая такая группа без своего `idle_timeout` получает его равным интервалу. Если `idle_timeout` задан явно и он короче интервала, проверка настроек отклоняет конфигурацию с понятным сообщением. Раньше в таком случае просто не стартовал sing-box. То же для настроек URLTest, сохранённых на дашборде. Интервалы вида `1h30m` теперь тоже распознаются.
- **Ядро sing-box при обновлении Prokop (A7).** Если sing-box ставил сам Prokop (варианты extended и extended-compressed), обновление пакета Prokop удаляло ядро вместе со старой версией. После обновления Prokop оставался без sing-box. Теперь ядро удаляется только при удалении Prokop.
- **Локальные и удалённые списки в одном правиле (A8).** У правила со списками доменов и IP из локальных файлов и по ссылке каждая генерация конфигурации пересобирала набор только из локальных файлов. Скачанные записи пропадали до следующего обновления списков, и этот трафик шёл мимо правила. Теперь набор такого правила не трогается до обновления списков, которое собирает его целиком. Если локальный файл пропал, остаётся предыдущий набор, а не урезанный. Новый набор заменяет старый одним переименованием.
- **Проверка конфигурации sing-box на роутере с малой памятью (B1).** Перед каждым запуском Prokop проверяет конфигурацию командой `sing-box check`. На роутерах с 256 МБ она сама могла занять столько памяти, что ядро завершало процессы. Теперь проверка идёт с ограничением памяти Go (`GOMEMLIMIT=32MiB`, `GOGC=25`). Так же и в диагностике.
- **Проверка скачанных списков в формате SRS (B2).** Раньше каждый скачанный бинарный список разворачивался в JSON, и на большом списке это требовало примерно вдвое больше памяти. Обновление списков было первым, что упиралось в память на 256 МБ. Теперь список проверяется командой `sing-box rule-set match`, которая читает его целиком без разворачивания. Повреждённый или обрезанный список по-прежнему отклоняется, и остаётся предыдущий.
- **Сохранение кэша FakeIP при остановке (B10).** Для sing-box, который ставит сам Prokop (варианты extended), procd давал процессу 5 секунд после сигнала остановки, а потом завершал его принудительно. На медленной флеш-памяти sing-box не успевал записать кэш FakeIP, и после перезапуска устройства получали новые адреса. Теперь у него 10 секунд. Это меньше 15 секунд, которые Prokop ждёт при остановке, так что остановка укладывается в прежнее время.

## Что проверено

- PASS: автоматические тесты, от root и в окружении как в CI (без root, без `uci`). Для каждого исправления есть тест, который падает на старом коде.
- PASS: проверка SRS на настоящем sing-box 1.12.9: собранный список принимается, обрезанный, испорченный и JSON вместо SRS отклоняются.
- NOT TESTED: на роутере. Не проверялись обновление пакета с установленным extended-compressed, расход памяти `sing-box check` и проверки SRS и сохранение кэша FakeIP при остановке. Скрипты пакета проверены с подменённым sing-box.
- Не сделано: старт без кэша списков, когда списки качаются через прокси (A9). Сейчас такой старт не проходит. Способ исправления ждёт решения.
