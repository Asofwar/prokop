# Идеи для Prokop из форков — 8 октября 2026

База сравнения: Prokop **2.28.3**, коммит `385be09cc73a84068c1b42f12d23d13b176f8b97`.
Изучены README, актуальные исходники и выбранные тесты восьми родственных проектов. Это обзор возможностей и план адаптации: работоспособность чужих реализаций на роутере в рамках этой работы не проверялась.

Главная рекомендация: сначала улучшить настройку DNS, выбор устройств, управление версией ядра и объяснение здоровья подключений. Затем добавить Smart Detect в виде рекомендаций. Xray и дополнительные туннели оставить отдельными проектами.

## 1. DNS-профили и DNS over QUIC

**Что найдено.** В slayer326 есть DoQ и готовые DNS-профили для правил, включая Яндекс и Xbox; FlowGate вынес выбор адресов в отдельный модуль. Профиль должен учитывать протокол, чтобы IP для UDP не превращался в ошибочный DoH URL.

**Что уже есть.** В Prokop есть DoH/DoT/UDP, список популярных DNS, bootstrap, failover и DNS-настройки секций. Новизна — связанный профиль с правильными полями и DoQ, а не добавление ещё одного IP в список.

**Как адаптировать.** Единый каталог «провайдер → поддерживаемые протоколы → адрес/порт/путь/SNI». Смена протокола сохраняет отдельно введённый пользовательский адрес для каждого протокола. Для DoQ добавить поддержку в backend, глобальные настройки, правила, диагностику и проверку возможностей ядра. Проверить взаимодействие с общим отключением QUIC и исходящим DNS-трафиком роутера.

**Проверка результата.** Переключение UDP → DoH → DoT → DoQ даёт валидную конфигурацию; ручной адрес не теряется; сервер с путём не принимается как DoQ; старые настройки не меняются при миграции.

Источники: [DoQ в backend](https://github.com/slayer326/forkop/blob/153012b38845c8167cf71b806d3ca889409daacc/forkop/files/usr/lib/singbox/dns.uc), [DNS-профили правил](https://github.com/slayer326/forkop/blob/153012b38845c8167cf71b806d3ca889409daacc/luci-app-forkop/htdocs/luci-static/resources/view/forkop/section.js), [проверки форм](https://github.com/slayer326/forkop/blob/153012b38845c8167cf71b806d3ca889409daacc/tests/luci_dns_presets.js), [каталог FlowGate](https://github.com/rock12/FlowGate/blob/b3f592820c02ea3c293ea30e3bfefbcb99784666/forkop/files/usr/lib/singbox/dns_presets.uc).

## 2. Здоровье узлов: отдельно задержка и передача данных

**Что найдено.** fix-urltest проверяет HTTPS 204 и полную загрузку 32 КБ; показывает причину отказа и возраст результата. Контроллер удерживает работающий узел после единичного сбоя, повторно проверяет резерв, использует медиану и порог выигрыша для смены ради скорости. После отказа закрывает только связанные с отказавшим узлом и группой соединения.

**Что уже есть.** Prokop 2.16.0 уже проверяет загрузку 32 КБ в Priority, использует отдельный probe-selector и минутный карантин. Переносить всю функцию как новую нельзя.

**Как адаптировать.** Начать с карточек «рукопожатие прошло / передача данных прошла / причина / проверено N секунд назад». Затем добавить накопление последовательных ошибок и антидребезг в существующий Priority. Расширение на URLTest рассмотреть отдельно. Состояние держать в RAM и сбрасывать при изменении узла или detour. Контрольные адреса сделать настраиваемыми.

**Проверка результата.** Одна ошибка не меняет узел; устойчивый отказ меняет его после проверки резерва; нет ухода напрямую, если все кандидаты отказали; успешный HTTPS не объявляется доказательством работы игрового UDP.

Источники: [правила выбора](https://github.com/shellovxx/fix-urltest/blob/397cfee0743aa6af129f47598d9261cea3a1a6a6/docs/smart-selection.md), [проверки алгоритма](https://github.com/shellovxx/fix-urltest/blob/397cfee0743aa6af129f47598d9261cea3a1a6a6/tests/health_selection.sh), [проверки контроллера](https://github.com/shellovxx/fix-urltest/blob/397cfee0743aa6af129f47598d9261cea3a1a6a6/tests/health_runtime.sh). База Prokop: [priority.uc](../../prokop/files/usr/lib/singbox/priority.uc), [2.16.0](../releases/2.16.0.md).

## 3. Единая политика устройств

**Что найдено.** Alice Mode в Trafira: режимы «только выбранные используют прокси» и «выбранные обходят прокси», выбор MAC, IP/подсети и интерфейсов. В панели устройств видны маршрут и причина выбора; обходящим клиентам выдаются реальные DNS-адреса вместо FakeIP.

**Что уже есть.** Prokop умеет фильтровать/исключать устройства по секциям и показывает их трафик. Новое — общий понятный экран и глобальная политика участия.

**Как адаптировать.** Страница «Устройства»: имя, MAC/IP, интерфейс, участие в Prokop, причина маршрута и ссылки на действующие правила. Для MAC использовать актуальное соответствие DHCP/neighbor; для клиентов за туннелем — IP/подсеть/интерфейс. DNS и nft должны применять одну политику. Отдельно определить приоритет относительно kill-switch: глобальное исключение не должно молча ослаблять уже включённую защиту.

**Проверка результата.** Проверить пустые списки обоих режимов, смену DHCP-адреса, IPv6, клиентов WireGuard и смешанные секционные правила. В интерфейсе явно объяснить поведение пустого списка.

Источники: [единая модель политики](https://github.com/petrouspetr-pixel/trafira/blob/b3832a92df1b411c4bd046d7421758223250cae8/trafira/files/usr/lib/config/alice.uc), [страница устройств](https://github.com/petrouspetr-pixel/trafira/blob/b3832a92df1b411c4bd046d7421758223250cae8/luci-app-trafira/htdocs/luci-static/resources/view/trafira/alice.js), [проверки маршрутизации](https://github.com/petrouspetr-pixel/trafira/blob/b3832a92df1b411c4bd046d7421758223250cae8/tests/alice_mode.sh), [проверки устройств](https://github.com/petrouspetr-pixel/trafira/blob/b3832a92df1b411c4bd046d7421758223250cae8/tests/alice_devices.sh).

## 4. Выбор конкретной версии ядра

**Что найдено.** forkop-mod и FlowGate позволяют выбирать конкретный релиз sing-box; FlowGate показывает extended/lx и предварительные релизы.

**Что уже есть.** У Prokop есть смена варианта ядра, обновление с откатом и выбор версии Prokop. Отдельного выбора релиза ядра в просмотренной базе не найдено.

**Как адаптировать.** Версия ядра, закрепление от автоматического обновления, отметка совместимости и переход на предыдущую версию одной операцией. Показывать только сборки для текущей архитектуры и пакетного менеджера. Не подключать новые ветки ядра только ради списка версий.

**Проверка результата.** Контрольная сумма, место для нового ядра и отката, проверка текущего конфига выбранным ядром, сохранение ручной остановки службы, восстановление старого ядра после ошибки.

Источники: [получение и установка версии](https://github.com/Gavr1024/forkop-mod/blob/9f495bfb6346be22138875a4cf821607b643c684/forkop/files/usr/lib/components/action.uc), [list-component-releases / install-component-version](https://github.com/rock12/FlowGate/blob/b3f592820c02ea3c293ea30e3bfefbcb99784666/forkop/files/usr/lib/components/action.uc).

## 5. Почему конкретное соединение выбрало этот маршрут

**Что найдено.** Screamshow добавляет отображение совпавших условий, обработку причины маршрута и расширение обрезанных условий. Новые точные свидетельства связаны с sing-box X; frontend не угадывает условие для непрозрачных rule-set или неоднозначных выражений.

**Что уже есть.** В Prokop есть Route Debugger и правило/выход в мониторинге. Новый шаг — объяснение конкретного совпавшего домена, подсети или набора правил непосредственно у живого соединения.

**Как адаптировать.** При наличии runtime-данных показать «совпало: domain_suffix=… / ip_cidr=… / rule-set …». Если ядро таких данных не отдаёт, оставить доступное объяснение и указать ограничение. Результат реконструкции по конфигурации маркировать отдельно от наблюдаемого совпадения.

**Проверка результата.** Проверить совпадения домена и подсети, инверсию, логические правила, сокращённые условия и несовпадающую версию runtime. Интерфейс должен оставаться рабочим на tiny/stable.

Источники: [выделение совпадений](https://github.com/Screamshow/forkop/blob/2fe5ada976fafaba55d9789b69d2bfb561297936/fe-app-forkop/src/forkop/tabs/monitoring/matchedConditions.ts), [неоднозначные и сокращённые условия](https://github.com/Screamshow/forkop/blob/2fe5ada976fafaba55d9789b69d2bfb561297936/fe-app-forkop/src/forkop/tabs/monitoring/routeConditions.ts), [представление причины](https://github.com/Screamshow/forkop/blob/2fe5ada976fafaba55d9789b69d2bfb561297936/fe-app-forkop/src/forkop/tabs/monitoring/routeReason.ts).

## 6. Smart Detect как помощник настройки

**Что найдено.** FlowGate анализирует ошибки direct-out и зависшие web-соединения, сравнивает доступность напрямую и через прокси. Есть повторное подтверждение, исключения и нормализация доменов по Public Suffix List.

**Что уже есть.** Prokop подбирает DPI-стратегию для заданных групп и целей. Это не обнаружение новых ресурсов, которым нужно правило.

**Как адаптировать.** Первая версия собирает рекомендации «напрямую не работает, через выбранный прокси работает» с временем и результатами проб. Кнопка применения создаёт правило через существующие snapshots/validation/reload. Автоматическое применение — отдельная выключенная опция после проверки алгоритма.

**Ограничения.** Ошибка HTTP, DNS или перегруженный сервер не доказывает блокировку. Не добавлять целый регистрируемый домен без предпросмотра: это может затронуть чужие поддомены. Ограничить параллельные пробы, память и частоту, не писать каждое наблюдение на flash. Локальные адреса и пользовательские исключения защищать всегда; набор исключений национальных сервисов сделать редактируемой политикой.

Источники: [проверки и исключения](https://github.com/rock12/FlowGate/blob/b3f592820c02ea3c293ea30e3bfefbcb99784666/forkop/files/usr/lib/service/smart_detect.uc), [зависшие соединения и PSL](https://github.com/rock12/FlowGate/blob/b3f592820c02ea3c293ea30e3bfefbcb99784666/forkop/files/usr/lib/service/smart_detect_plus.uc), [фоновый цикл](https://github.com/rock12/FlowGate/blob/b3f592820c02ea3c293ea30e3bfefbcb99784666/forkop/files/usr/lib/service/smart_detect_runner.uc).

## 7. Автоматическая группировка больших подписок

**Что найдено.** NetShift группирует узлы по флагу страны или префиксу, строит URLTest внутри групп и над группами, сохраняет ручной выбор. Подписки могут иметь отдельные имена и блоки на дашборде.

**Что уже есть.** Prokop уже принимает несколько подписок и умеет вручную задавать URLTest/Priority, фильтры по странам и регулярным выражениям. Новизна — автоматическое представление и навигация по большой подписке.

**Как адаптировать.** Режимы «без групп / страна / префикс», предпросмотр групп перед применением, отдельная метка источника подписки и устойчивые идентификаторы. В первом этапе можно сделать только группировку в интерфейсе, без новой иерархии runtime-селекторов.

**Проверка результата.** Обновление подписки не сбрасывает ручной выбор; одинаковые имена узлов не объединяют разные подключения; узлы без флага не теряются. Несколько подписок сами по себе не считать новой функцией.

Источники: [настройки группировки](https://github.com/yandexru45/netshift/blob/6e4bec7214f0650ce8c5bbb2f3dab3f3fdc6a352/README.md), [sing_box_build_subscription_groups и subscription_group_mode](https://github.com/yandexru45/netshift/blob/6e4bec7214f0650ce8c5bbb2f3dab3f3fdc6a352/netshift/files/usr/bin/netshift).

## 8. DoH с mTLS

**Что найдено.** Trafira передаёт пути клиентского сертификата и закрытого ключа только выбранному DoH-хосту. Проверяет привязку к hostname и форму путей.

**Как адаптировать.** Дополнительные поля конкретного DNS-профиля: hostname, сертификат, ключ. Файлы хранить с ограниченными правами; содержимое ключа не отправлять в UI и отчёты. Проверять поддержку полей установленным sing-box: правильная UCI-конфигурация ещё не доказывает TLS-совместимость.

**Польза.** Собственный защищённый DNS; массовому пользователю без такого сервера не требуется. Проверить основной сервер, failover, несовпадающий хост, отсутствующие файлы и восстановление снимков.

Источники: [host-scoped mTLS](https://github.com/petrouspetr-pixel/trafira/blob/b3832a92df1b411c4bd046d7421758223250cae8/trafira/files/usr/lib/singbox/dns.uc), [контракт и отрицательные сценарии](https://github.com/petrouspetr-pixel/trafira/blob/b3832a92df1b411c4bd046d7421758223250cae8/tests/dns_mtls.sh).

## 9. Готовая политика для игровых консолей

**Что найдено.** В FlowGate выбранным IP добавляют ранний выход из TPROXY для UDP; TCP продолжает идти через обычные правила.

**Как адаптировать.** Профиль устройства «игровой UDP напрямую, сервисы/магазин через прокси», с явным выбором приложений/портов и объяснением совместимости с kill-switch. Желательно собирать профиль из существующих правил Prokop, чтобы отдельный ранний nft-return не обходил защиту.

**Ограничение.** Это не гарантия NAT Type 1/Open NAT: результат зависит от CGNAT, firewall, UPnP и сервера игры. Отдельно проверить DNS/FakeIP, UDP 443 и игры, которым самим нужен обход.

Источник: [game_console_optimizer / game_console_ips](https://github.com/rock12/FlowGate/blob/b3f592820c02ea3c293ea30e3bfefbcb99784666/forkop/files/usr/lib/nft/apply.uc).

## 10. Именованные профили конфигурации

**Что найдено.** forkop-mod хранит «слоты» для случаев доступной и недоступной сети и переключает их по ping; есть выбор при загрузке и запасной адрес проверки.

**Что уже есть.** Снимки и последняя рабочая конфигурация Prokop предназначены для восстановления. Они не являются пользовательскими режимами «работа / игры / резервная сеть».

**Как адаптировать.** Сначала ручные именованные профили с предпросмотром diff и применением через существующую транзакцию. Автопереключение — позже, по нескольким проверкам, с гистерезисом и паузой после ручного выбора. Ping одного адреса не должен решать судьбу всего конфига.

**Проверка результата.** Не терять правки пользователя; при отказе нового профиля возвращать предыдущий; ручная остановка остаётся остановкой; переключение не ослабляет kill-switch.

Источник: [хранение и переключение слотов](https://github.com/Gavr1024/forkop-mod/blob/9f495bfb6346be22138875a4cf821607b643c684/forkop/files/usr/lib/config/slots.uc).

## 11. Второе ядро Xray по секциям

**Что найдено.** forkop-mod выбирает движок секции, генерирует конфигурацию Xray, управляет отдельным процессом и геоданными; в тестах есть dual-core и primary-plane сценарии.

**Как адаптировать.** Пилот с одной секцией Xray через локальный SOCKS sidecar и единым входом маршрутизации Prokop. Поддержку URLTest/Priority, подписок, всех видов DNS и полного native TPROXY добавлять по отдельным контрактам.

**Почему позже.** Prokop уже поддерживает xHTTP, VLESS Encryption и ML-KEM REALITY через extended. Нужно сначала назвать конкретный профиль, который работает только в Xray. Второй runtime увеличивает память, сложность владения процессами, диагностики, обновлений и отката.

Источники: [генератор Xray](https://github.com/Gavr1024/forkop-mod/blob/9f495bfb6346be22138875a4cf821607b643c684/forkop/files/usr/lib/xray/generator.uc), [dual-core контракт](https://github.com/Gavr1024/forkop-mod/blob/9f495bfb6346be22138875a4cf821607b643c684/tests/xray_dual_core.sh), [отдельная проверка плоскости маршрутизации](https://github.com/Gavr1024/forkop-mod/blob/9f495bfb6346be22138875a4cf821607b643c684/tests/xray_primary_plane.sh).

## 12. Временная удалённая поддержка

**Что найдено.** Screamshow создаёт отдельную временную userspace-сессию Tailscale, сохраняет работающую основную установку, показывает срок 30 минут и кнопку отключения. Авторизация и SSH-доступ управляются отдельной подсистемой.

**Как адаптировать.** Опциональный компонент с явным стартом пользователем, таймером, отзывом доступа и журналом сессий. Для Prokop не копировать чужой фиксированный ключ оператора: идентичность и допустимые права поддержки должны задаваться владельцем продукта. Объём доступа показывать до начала сессии.

**Ограничения.** Это доступ к роутеру, не просто обмен диагностикой. Нужно учитывать RAM/flash, политику tailnet, права LuCI, перезагрузку и отключение. Отзыв соединения не отменяет изменения, которые оператор уже сделал с правами root.

Источники: [модель и ограничения](https://github.com/Screamshow/forkop/blob/2fe5ada976fafaba55d9789b69d2bfb561297936/docs/remote-support.md), [жизненный цикл сессии](https://github.com/Screamshow/forkop/blob/2fe5ada976fafaba55d9789b69d2bfb561297936/tests/support_session_vm.sh).

## 13. WDTT / OlcRTC

**Что найдено.** Topkop добавляет самостоятельные provider-действия секций, парсинг URI/подписок, локальные порты, установку, состояние и диагностику. Для WDTT есть отдельный flow авторизации/капчи.

**Как адаптировать.** Экспериментальные подключаемые провайдеры на базе существующей модели Zapret/ByeDPI: свой validator, runtime, статус, принадлежность процесса, snapshot и удаление. Интерфейс должен честно показывать необходимость внешней авторизации и ограничения конкретного транспорта.

**Проверка результата.** Перезапуск ждёт освобождения портов; ошибочная подписка не ломает остальные секции; процессы не теряются; uninstall снимает только принадлежащее компоненту состояние. До этого перенос не считать готовой пользовательской функцией.

Источники: [возможности и зависимости](https://github.com/win64exe/topkop/blob/959138d53b49d129589f591ff87ad2ca39cae906/README.md), [WDTT runtime](https://github.com/win64exe/topkop/blob/959138d53b49d129589f591ff87ad2ca39cae906/forkop/files/usr/lib/providers/wdtt/runtime.uc), [OlcRTC runtime](https://github.com/win64exe/topkop/blob/959138d53b49d129589f591ff87ad2ca39cae906/forkop/files/usr/lib/providers/olcrtc/runtime.uc).

## Что уже есть или не стоит переносить напрямую

- **Автоподбор DPI, snapshots, LKG, rollback, read-only LuCI, мониторинг устройств, уведомления, зеркала и кэш списков** уже входят в Prokop.
- **Проверка узла полной загрузкой** уже есть в Priority: полезно улучшать её UI и выбор, а не объявлять новой функцией.
- **Несколько подписок, фильтрация стран и имени** уже есть. Автоматическая группировка — отдельная добавка.
- **Twitch и игровые community-списки** уже есть. Можно сравнивать содержимое, но сама кнопка Twitch не новая.
- **Watchdog с остановкой всей службы и возвратом DNS** из Screamshow нельзя переносить без адаптации к kill-switch, ручной остановке и существующему DNS-failsafe Prokop.
- **Обновление ядра без резервной копии ради экономии flash** из forkop-mod противоречит существующему откату Prokop. Можно оптимизировать хранение, сохранив возможность восстановления.
- **Отключение TLS-проверки подписок** из NetShift не нужно для перечисленных UX-идей и не рекомендуется к переносу.
- **Входящий AmneziaWG-сервер** FlowGate расширяет назначение продукта; локальные серверы в Prokop ранее сознательно убраны. Вернуться к идее только при явной потребности.
- Заявления README о «гарантированном Open NAT», «идеальном пинге» и отсутствии риска при обновлении не использовать как подтверждение качества реализации.

## Порядок реализации

1. DNS-профили + DoQ; затем версия/закрепление ядра. Это самостоятельные функции с относительно чётким контрактом.
2. Карточки здоровья узлов и общий экран устройств. Использовать уже имеющиеся backend-данные и механизмы применения.
3. Причина маршрута, группировка подписок и Smart Detect в режиме рекомендаций.
4. mTLS и консольные профили — по реальному сценарию пользователя.
5. Именованные профили, Xray, удалённая поддержка и WDTT/OlcRTC — отдельные инициативы после определения требований.
