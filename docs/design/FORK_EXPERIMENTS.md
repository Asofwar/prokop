# Эксперименты с идеями из форков

Ветка `feature/fork-ideas` реализует первый вариант всех 13 направлений из
[обзора форков](FORK_IDEAS_2026-10-08.md). В релиз 2.29.0 входят направления
из таблицы ниже; локальные провайдеры (Xray, WDTT, OlcRTC) и временный доступ
поддержки через Tailscale остаются только в этой ветке (см. ниже). Новые
режимы обхода включаются явно.

| Идея | Где попробовать | Поведение первого варианта |
| --- | --- | --- |
| DNS-профили и DoQ | Settings → DNS; действие DNS в Rules | Профиль изменяет существующие поля протокола и адреса. Пользовательские адреса сохраняются отдельно для каждого протокола в пределах открытой формы. DoQ использует QUIC/853, поддерживает другой порт, запрещает путь и query. |
| Здоровье Priority | Experiments → Node health | Отдельно показывает проверку соединения, загрузку payload, задержку и причину ошибки. Переключение после двух последовательных ошибок; медиана трёх задержек и порог улучшения 50 мс / 20% для выбора более быстрого узла. Существующая проверка payload 32 KiB и карантин сохранены. |
| Политика устройств | Device routing | Глобальный allow/deny по IP/подсети, MAC, интерфейсу. Пустой allow отправляет всех напрямую, пустой deny оставляет всех в Prokop. Обход действует для IP-списков и устройств со своим внешним DNS; устройства с DNS роутера получают FakeIP для доменов из списков (см. ограничение ниже). Диагностика показывает наблюдаемые устройства и причину решения. |
| Версии ядра | Settings → Core version | Выбор конкретного совместимого релиза sing-box-extended из настроенного источника с опубликованным checksum. Можно закрепить тег для обычных обновлений Extended. Сохраняются существующие проверка архива и откат установки. Зеркало не обходится: пока оно предоставляет только latest, доступны только его данные. |
| Причина маршрута | Monitoring → детали соединения | Runtime payload имеет приоритет. Восстановленное по метаданным условие подписывается отдельно; непрозрачные и неоднозначные условия не выдаются за точное совпадение. |
| Smart Detect | Experiments | Находит домены в недавних ошибках или принимает домен вручную. Сравнивает два локальных SOCKS-входа отдельного временного sing-box: direct и выбранную секцию. Две проверки с интервалом ≥120 секунд дают рекомендацию. DNS/сертификатные ошибки не подтверждают блокировку. Применение добавляет домен в ожидающие изменения; Save & Apply создаёт снимок и валидирует конфигурацию. |
| Группировка подписок | Dashboard → Group nodes | По стране (метаданные или флаг) либо префиксу до разделителя ` \| ` / `/`. Это представление интерфейса: теги, выбранные узлы, URLTest и Priority не переписываются. Выбор хранится локально в браузере. |
| DoH mTLS | Settings → DNS | Только главный DoH-сервер с совпадающим hostname получает пути сертификата и ключа. Файлы уже должны быть на роутере; приватный ключ не переносится в JSON как содержимое. Другие DNS-серверы сертификат не получают. |
| Игровая консоль | Device routing → Game console profile | IP/подсети консолей: TCP через выбранную секцию, UDP напрямую, реальные DNS-адреса только при собственном внешнем DNS консоли. Не обещает Open NAT. Глобальная политика устройств и section kill-switch несовместимы с этим режимом и вызывают отказ валидации. |
| Именованные профили | Experiments → Configuration profiles | Сохраняют текущую **применённую** конфигурацию в ручной снимок. Активация использует существующий guarded restore с проверками конкурентного изменения и откатом. Имя уникально; удаление имени сохраняет снимок в History. Автоматический выбор профиля по WAN — следующий этап. |

## Что осталось только в `feature/fork-ideas`

В релиз 2.29.0 входят все направления из таблицы выше. Следующие части
остаются только в ветке `feature/fork-ideas` и в релиз не включены, потому
что требуют отдельной проверки на роутере и дополнительного сетевого runtime:

- Xray по секциям и локальные провайдеры WDTT (qwdtt) и OlcRTC: страница
  Local providers, `experiments/sidecars.uc`, `experiments/sidecar_config.uc`,
  `providers/wdtt`, `providers/olcrtc`, служба `prokop-sidecars`, отдельный
  пользователь `prokop-sidecar` и исключение его сокетов из output-перехвата
  по UID.
- Временный доступ поддержки через Tailscale (`experiments/support.uc`,
  раздел Experiments → Temporary support access, команды
  `support_session_*`).

Их описание, ограничения и тесты (`sidecar_prepare.sh`,
`support_session_concurrency.sh`, `support_session_expiry.sh`) находятся в
той ветке. Раздел UCI `sidecar`, сохранённый сборкой из этой ветки,
релизом игнорируется.

## Проверки и границы подтверждения

Автоматические проверки покрывают генерацию DNS и mTLS, nft-политику обхода
и игр, отказ при kill-switch, изоляцию Smart Detect, классификацию ошибок, профильные команды,
отсутствующие зависимости, LuCI 24.10/25.12, группировку и причины маршрута.
Выполняются также существующие backend/frontend проверки и сборка интерфейса.

Результаты проверки ветки (8 октября 2026):

- Frontend: 115 файлов, 1018 тестов; Prettier, ESLint, TypeScript и production build проходят.
- Полный backend-прогон: 482 проверки; четыре первоначальных сбоя исправлены
  и проверены повторно (состав вкладок и меню, shell inventory, конкурентный apply).
- Дополнительные проверки гистерезиса проходят.
- Syntax: 119 файлов на двух версиях ucode; shell-проверки проходят.
- Проверки, которым нужны отсутствующие реальные nft/sing-box, пропускаются
  штатно; это не подтверждение работы на роутере.

Стенд разработки не является OpenWrt-роутером. NAT игровых консолей
и сертификатная аутентификация DoH требуют проверки на целевом устройстве.
Начинать проверку следует с резервного снимка и одного тестового устройства.

## Проверка логики ветки и регрессии

Повторное review `d0ed3102` относительно `385be09c` выявило и исправило:

- Потерю пользовательского DNS при нескольких последовательных пресетах;
  распознавание сохранённого singleton-списка DNS как пресета. Добавлены
  unit-тесты и проверка реальных LuCI-модулей для 24.10/25.12.
- Маскирование ошибки Experiments исключением `_ is not a function` при
  пустом или некорректном stdout. Добавлена проверка реального command helper.
- Обход двухошибочного гистерезиса Priority при совпадающих active/fastest
  таймерах и отказе active во время fastest-only пробы. Новые тесты исполняют
  настоящий fastest selector, а не его заглушку.
- (Только `feature/fork-ideas`.) Гонку Start/Stop поддержки, оставлявшую daemon без session/deadline.
  Stop теперь возвращает `support_busy` во время Start: дождаться окончания
  и повторить Stop. Watchdog не ждёт занятого lock, чтобы завершить свой
  daemon по deadline; старт перепроверяет lease и identity после блокирующих
  операций. Разные сессии с одинаковым deadline различаются lifetime token.
- (Только `feature/fork-ideas`.) Коллизию имени провайдера `manifest` с manifest.json: native конфиги теперь
  используют `<name>.config.json`. Отклонённая подготовка не снимает traversal
  permission родительского каталога; приватные конфиги/data остаются закрыты.
- Отправку кешированных FakeIP напрямую при включении bypass/game policy:
  synthetic destinations остаются на пути трансляции sing-box.
- Перехват DNS к самому роутеру/LAN новыми device/game правилами: теперь
  optional DNS gates сохраняют router-local/private/delegated IPv6 ответы
  и явные source/destination exclusions. Остальные, ранее настроенные
  source-aware DNS-политики не отменяются.

Важное ограничение: сохранённые FakeIP и ответы через локальный dnsmasq могут
продолжать использовать обычные правила sing-box до обновления кеша. Исключение
DNS к LAN не означает, что такой резолвер обязательно выдаёт реальные адреса.
Фактическая доставка пакетов и ответы DHCP-hostnames требуют router-теста.

Локальная проверка изменений (Windows + WSL, без OpenWrt):

- Frontend: **116 файлов / 1020 тестов PASS**; TypeScript, ESLint, Prettier,
  production build проходят.
- Targeted backend: **18 проверок PASS**, включая новые concurrency/sidecar/
  Priority тесты, DNS, nft generation и существующие контрактные проверки.
- Syntax: **119 файлов × 2 режима PASS**; ShellCheck: **524 файла PASS**.
- Полный backend-прогон: **488 запусков, 6 FAIL**. Четыре проверки реального
  nft/dataplane не проходят на WSL kernel (в частности отсутствует nft fib);
  отказ пустого ruleset воспроизводится также на родительском commit.
  `ui_state_poll_cost` нестабилен под полной нагрузкой, но отдельный повтор
  5 раз проходит. Шестой FAIL — вложенный агрегатор `tests/run.sh` из-за тех
  же nft-проверок. Полный backend **не объявляется PASS**.
- LuCI harness дополнен глобальным navigator из window.navigator: три
  существующих теста больше не зависят от наличия browser global в Node 18.

Новые тесты: `priority_fastest_hysteresis.sh`, `luci_experiments_errors.sh`,
`fe-app-prokop/src/prokop/tests/dnsProfiles.test.ts` (а также
`support_session_concurrency.sh` и `sidecar_prepare.sh` — только в
`feature/fork-ideas`). Проверки production nft/FakeIP и DoH mTLS на роутере
по-прежнему нужны.

## Проверка перед релизом 2.29.0

- Закреплённая или выбранная версия sing-box-extended устанавливается только
  при опубликованной контрольной сумме ассета; без неё установка отказывает.
  `check_update` сравнивает с закреплённым тегом, а не с latest.
- DoQ отклоняется проверкой требований на ядре без `with_quic`; клиентский
  сертификат DoH требует sing-box 1.13.0+, существующих файлов сертификата
  и ключа. Ключ, читаемый всеми, даёт предупреждение (содержимое не читается).
- Страницы Device routing и Experiments показывают статусы, причины и
  вердикты Smart Detect словами вместо кодов и JSON; динамические подписи
  переданы в `_()` литералами, чтобы каталог переводов их сохранял.

Известное ограничение политики устройств: DNS-запросы к самому роутеру
(dnsmasq) не перенаправляются, поэтому устройство, переведённое в обход и
использующее DNS роутера, продолжает получать FakeIP для доменов из списков,
и такой трафик идёт через sing-box по обычным правилам. Обход полностью
действует для IP-списков и для устройств со своим внешним DNS.
