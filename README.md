Prokop работает на основном домашнем роутере, поэтому главный принцип проекта — **не ломать обычный интернет и доступ к роутеру**. Каждое изменение конфигурации можно откатить, рабочая конфигурация запоминается, а там, где безопасность нельзя доказать, Prokop останавливается и закрывает доступ (fail closed), а не пропускает трафик напрямую.

```sh
wget -qO- https://asofwar.github.io/prokop/install.sh | sh
```

## Главное

| | |
|---|---|
| 🧭 **Маршрутизация** | TPROXY и FakeIP, списки доменов и подсетей, подписки, секции с разными подключениями |
| 🛡️ **Обход DPI** | Zapret, Zapret2 и ByeDPI из интерфейса; **автоподбор стратегии** в изолированной песочнице |
| ♻️ **Надёжность** | снимки конфигурации, «последняя рабочая конфигурация», транзакционное восстановление с откатом |
| 🔍 **Наблюдаемость** | обзор здоровья системы, диагностика DNS/TCP/HTTP/HTTPS, проверка маршрута, мониторинг соединений |
| 🔒 **Безопасность** | VPN kill-switch, режим «только чтение» для LuCI, секреты не попадают в интерфейс, логи и отчёты |
| 📦 **Свой канал релизов** | GitHub Pages с резервом через GitHub Releases, каждый пакет сверяется по SHA-256 |

## Установка

Одна команда на роутере. Установщик сам подтянет зависимости, ядро sing-box и списки:

```sh
wget -qO- https://asofwar.github.io/prokop/install.sh | sh
```

Если `asofwar.github.io` недоступен, тот же установщик есть в GitHub Releases:

```sh
wget -qO- https://github.com/Asofwar/prokop/releases/latest/download/install.sh | sh
```

После установки страница находится в LuCI: **Службы → Prokop**. Команда на роутере — `prokop`.

<details>
<summary>Параметры установщика</summary>

Параметры передаются через `sh -s --`, например:

```sh
wget -qO- https://asofwar.github.io/prokop/install.sh | sh -s -- --sing-box tiny
```

Полный список — `| sh -s -- --help`.

Установщик и встроенное обновление работают через канал `https://asofwar.github.io/prokop` (GitHub Pages). Если его метаданные недоступны, они переключаются на GitHub Releases репозитория `Asofwar/prokop`. Каждый пакет сверяется с SHA-256 из метаданных канала. Подробности — в [docs/fork-distribution.md](docs/fork-distribution.md).

</details>

<details>
<summary>Зеркало зависимостей (по желанию)</summary>

По умолчанию зеркало выключено: пакеты OpenWrt идут из официальных фидов, списки, наборы правил, sing-box-extended и Zapret-Manager — из исходных репозиториев. Если до них плохо достучаться, подключите своё зеркало явно:

```sh
wget -qO- https://asofwar.github.io/prokop/install.sh | sh -s -- --mirror https://mirror.example.org
```

На установленном роутере то же самое — `uci set prokop.settings.mirror_base_url=URL && uci commit prokop`, затем `/usr/share/prokop/mirror-migration.sh`, чтобы перевести фиды OpenWrt на зеркало. Выключение — пустое значение; фиды своего зеркала возвращаются вручную из резервной копии `*.pre-forkop-mirror` (у копии прежнее имя, см. [docs/fork-distribution.md](docs/fork-distribution.md)).

Зеркало ускоряет только зависимости: APK-ключ зеркала и его фид пакетов роутер не принимает никогда, сам Prokop всегда приходит из релизов `Asofwar/prokop`. Зеркало публикует индекс готовых платформ, и установщик отказывается менять репозитории пакетов, пока не убедится, что нужная комбинация версии и архитектуры там есть. Как поднять своё зеркало — [ops/mirror/README.md](ops/mirror/README.md).

</details>

## Возможности

### 🧭 Маршрутизация

- Прозрачный перехват через TPROXY и FakeIP, режимы включения и исключения, смешанный режим.
- Списки доменов и подсетей — встроенные и свои. Встроенные наборы правил, в том числе для игровых сервисов: Blizzard, Sony, Bungie, Riot, Twitch, Nintendo, Epic Games, Valve и другие.
- Исключение отдельных устройств из маршрутизации по секциям.
- BitTorrent, распознанный sing-box, можно отправлять напрямую, мимо правил.

### 🔌 Подключения

- Share-ссылки `vless://`, `vmess://`, `trojan://`, `ss://`, `socks://`, `hysteria2://`, вставленный JSON, подписки с автообновлением.
- **Никаких списков разрешённых провайдеров**: работает любая HTTPS-подписка, проверка сертификатов не отключается. Поддерживаются дополнительные HTTP-заголовки подписки, разбор `xray_json`, настройки xHTTP от Remnawave, VLESS Encryption и постквантовый обмен ключами REALITY.
- Каскад подключений, привязка к интерфейсам, URLTest и группы Priority с отбором по странам и регулярным выражениям. Узел можно проверять настоящей загрузкой, а не только рукопожатием. Выбранный сервер сохраняется после перезагрузки роутера.

### 🌐 DNS

- Собственный резолвер sing-box, резервный DNS, автопереключение при отказе, режимы работы с dnsmasq, защита от утечек.
- EDNS Client Subnet для ответов CDN ближе к вам.
- Prokop замечает, если настройки DNS роутера изменили в обход него или если обычный DNS по пути перехватывает провайдер.

### 🛡️ Обход DPI и автоподбор стратегий

- Zapret, Zapret2 и ByeDPI подключаются как отдельные компоненты — установка и обновление прямо из интерфейса, в том числе zapret-manager.
- **Автоподбор DPI** сам ищет рабочую стратегию: проверяет кандидатов на настоящих сайтах, оценивает результат и предлагает лучший вариант. Пробы идут в отдельной таблице nftables, через свою очередь и временный nfqws, с выделенным диапазоном портов — production-трафик и рабочая конфигурация во время эксперимента не меняются. Применение — вручную или по расписанию, с проверкой и откатом.

### ♻️ Надёжность и восстановление

- **Снимки конфигурации**: создать, сравнить (с маскировкой секретов), восстановить, удалить.
- **Транзакционное восстановление**: перед восстановлением сохраняется текущая конфигурация; если новая не поднялась, Prokop возвращает прежнюю. Пока состояние не доказано рабочим, DPI-трафик остаётся под защитным правилом.
- **Последняя рабочая конфигурация** обновляется только после успешного запуска — неудачная попытка рабочей не станет.
- Обновление доводится до конца и через `opkg`, и через `apk`; смена ядра sing-box и обновление откатываются при неудаче.
- Записи на флеш атомарные: файл пишется целиком или не пишется вовсе, без лишних перезаписей.

### 🔍 Наблюдаемость

- **Обзор**: здоровье службы, DNS и автоподбора. Если данных нет, интерфейс так и пишет, а не показывает устаревшее как текущее.
- **Диагностика**: проверки DNS, TCP, HTTP и HTTPS, FakeIP, маршрутов и подключений; проверка маршрута для домена или адреса; отчёт для поддержки одной кнопкой (с предупреждением о приватных данных).
- **Мониторинг**: живые соединения с правилом, выходом и стратегией DPI.
- Диагностика различает **наблюдаемые**, **настроенные** и **смоделированные** данные и не выдаёт одно за другое.

### 🔒 Безопасность

- **VPN kill-switch** для отдельной секции: если VPN, sing-box или сам Prokop не работают, трафик её клиентов блокируется, а не уходит напрямую. Политика переживает остановку Prokop, перезагрузку фаервола и роутера.
- **Режим «только чтение»** для пользователей LuCI: просмотр состояния, диагностика и список снимков — без запуска команд с изменениями и без доступа к сырой конфигурации.
- Пароли, ключи, UUID и адреса подписок с токенами маскируются в интерфейсе, диагностике и отчётах. Clash API всегда защищён секретом.
- Prokop никогда не трогает sing-box, который ему не принадлежит: если владение процессом неоднозначно, операция отказывает, а не снимает защиту.

## Интерфейс

Всё управление — в LuCI, **Службы → Prokop**. Интерфейс полностью на русском.

| Страница | Что там |
|---|---|
| **Обзор** | состояние службы и компонентов, здоровье DNS, карточка автоподбора DPI |
| **Правила** | секции маршрутизации, подключения, подписки, списки, kill-switch |
| **Мониторинг** | живые соединения, узлы и группы, журнал |
| **Диагностика** | проверки связности, проверка маршрута, отчёт для поддержки |
| **Автоподбор DPI** | группы, цели, рекомендации, расписание, применение и откат |
| **История и восстановление** | снимки конфигурации, сравнение, восстановление, последняя рабочая конфигурация |
| **Настройки** | DNS, сеть, обновления Prokop, sing-box, компонентов и списков |

Каждый видимый элемент управления либо работает от начала до конца, либо выключен с понятной причиной, либо не показывается. Вёрстка проверяется на ширине 1440, 1024 и 768 пикселей.

## Совместимость

| | |
|---|---|
| **OpenWrt** | 24.10 (`opkg`, ipk), 25.12+ (`apk`) |
| **Архитектура** | пакеты Prokop от архитектуры не зависят; зеркало зависимостей обслуживает только платформы из своего индекса (Filogic `aarch64_cortex-a53`, Rockchip `aarch64_generic`) |
| **Ядро** | sing-box: по умолчанию `tiny`, `stable` и `extended` — по выбору |
| **Память** | работает на роутерах с 256 МБ, есть режим малой памяти |

## Переход с Forkop

Prokop — это Forkop под новым именем: пакеты `prokop`, `luci-app-prokop` и `luci-i18n-prokop-ru`, настройки в `/etc/config/prokop`, страница **Службы → Prokop**. Встроенное обновление Forkop ищет пакеты `forkop` и на Prokop не переведёт, поэтому переход делает установщик. На роутере с Forkop — и со сборкой [slayer326/forkop](https://github.com/slayer326/forkop), и с прежними сборками этого форка любой версии 1.0.x — выполните ту же команду, что и для установки:

```sh
wget -qO- https://asofwar.github.io/prokop/install.sh | sh
```

Установщик найдёт Forkop, покажет, что собирается сделать, и спросит подтверждение. Без терминала (из скрипта, через `ssh router 'команда'`) подтверждение даётся флагом `| sh -s -- --confirm-legacy-migration`; без него установщик ничего не меняет и объясняет, что делать.

<details>
<summary>Что переносится и что будет, если что-то пойдёт не так</summary>

**Переносится:**

- все настройки: секции, подключения, подписки, списки и наборы правил, DNS, исключённые устройства — `/etc/config/forkop` становится `/etc/config/prokop`, после чего к нему применяются обычные миграции конфигурации;
- файлы состояния из `/etc/forkop` и резервные копии настроек из `/etc/forkop-backups` — в `/etc/prokop` и `/etc/prokop-backups`;
- установленный sing-box (tiny, stable или extended) — заново он скачивается, только если бинарник пропал;
- своё зеркало, если оно было включено; бывшие зеркала upstream (`mirror.infotechtg.ru`, `mirror.51343.ru`) выключаются, как при любой установке форка;
- состояние службы: если Forkop был включён и работал, Prokop включается и запускается, если был выключен — остаётся выключенным;
- права пользователей LuCI на просмотр и администрирование и настройки страниц в браузере (фильтры мониторинга, цели проверки связности, время последней диагностики).

Кэш подписок Forkop не переносится: Prokop скачивает подписки заново.

**Kill-switch остаётся закрытым всё время перехода.** Если для секций был включён VPN kill-switch, клиенты этих секций на время переключения остаются без интернета, а не уходят напрямую: правила Forkop снимаются только после того, как Prokop применит свои. Ненадолго прерываются и остальные подключения — sing-box перезапускается уже под Prokop.

**Если что-то пошло не так.** Ошибка до удаления Forkop откатывает всё: пакеты Prokop и `/etc/config/prokop` удаляются, Forkop остаётся в прежнем состоянии. Ошибка после удаления Forkop оставляет настройки Prokop и резервные копии на месте, а службу — выключенной; установщик печатает пути к копиям и следующие шаги. Прерванный переход (обрыв SSH, перезагрузка) продолжается с того же места повторным запуском той же команды.

После перехода закладки на старую страницу LuCI (`admin/services/forkop`) не открываются — откройте **Службы → Prokop**. Команда на роутере теперь `prokop`, а не `forkop`.

</details>

## Чем отличается от Forkop

<details>
<summary>Свой канал релизов и загрузки, которые не падают от одной неудачи</summary>

Оригинал полагается на сторонние источники: пакеты OpenWrt, списки маршрутизации, релизы. Если что-то из этого недоступно, установка обрывается на середине, а роутер остаётся в непонятном состоянии. Здесь релизы публикуются в собственный статический канал на GitHub Pages с резервом через GitHub Releases, каждый пакет проверяется по SHA-256, а ни ключ, ни фид пакетов чужого зеркала роутер не принимает.

У каждого источника данных есть резерв:

- **Списки и наборы правил** при недоступности основного адреса (или вашего зеркала) переключаются на jsDelivr и GitHub — и для текстовых списков, и для бинарных `.srs`.
- **DNS**: если системный резолвер не отвечает, загрузка идёт через резервный DNS. При настроенном прокси загрузка остаётся через него, а не в обход.
- **Кэш**: при любой ошибке сохраняется последняя рабочая версия списков. Обновление применяется целиком либо не применяется вовсе.
- **Холодный старт**: после перезагрузки роутера обновление списков ждёт сети, а списки, доступные только через прокси, скачиваются через временный sing-box.

</details>

<details>
<summary>Обновление, которое доводится до конца</summary>

Самая частая жалоба на подобные проекты — «обновился, и всё отвалилось». Здесь закрыты отдельные причины этого:

- `opkg` на части сборок OpenWrt 24 вызывает скрипт удаления без аргумента — отметка «служба работала» терялась, и служба не поднималась обратно.
- Процесс sing-box завершается не мгновенно, и запуск успевал начаться, пока старый процесс ещё жив.
- `procd` несколько секунд отдаёт PID уже завершившегося процесса, и это принималось за чужой процесс.

Обновление через `opkg` и `apk` работает одинаково, вручную перезапускать ничего не нужно.

</details>

<details>
<summary>Меньше лишнего и мелочи, заметные каждый день</summary>

- Вырезан локальный сервер и настройки, нужные доле процента пользователей.
- QUIC при первой установке принудительно выключен.
- По умолчанию ставится `sing-box-tiny` — меньше памяти на роутерах с 256 МБ.
- Меньше жёстко зашитых значений, из-за которых sing-box стартовал с невалидной конфигурацией.
- URLTest показывает текущий выбранный узел; карточки Priority свёрнуты и запоминают, что вы раскрыли.
- В журнале видно, удалось ли автоматическое восстановление после неудачного запуска.
- Если браузер показывает старую версию интерфейса из кэша, появляется предупреждение.

</details>

| `tests/` | тесты бэкенда, установщика и миграций |

Тесты бэкенда — `tests/run.sh` (подробнее — [tests/runner/README.md](tests/runner/README.md)). Интерфейс — `yarn ci` в `fe-app-prokop/`: форматирование, линтер, тесты и сборка. Пакеты — `./build.sh X.Y.Z`.

Релиз выпускается только из `main`: workflow **Build packages** с `release_tag` = версии из `RELEASE_VERSION` и `publish_release` = true сам создаёт тег и GitHub Release, а описание берёт из `docs/releases/X.Y.Z.md`. После сборки workflow **Publish release channel** заново собирает `https://asofwar.github.io/prokop` из последних 8 релизов; если чего-то не хватает, публикация отменяется и остаётся предыдущая версия сайта. Номер — строго `X.Y.Z` без `v`; опубликованная версия под тем же номером не пересобирается. Нумерация Prokop начинается с **2.0.0** — больше любой версии Forkop 1.0.x, поэтому переход не выглядит как откат. Подробно — в [VERSIONING.md](docs/releases/VERSIONING.md).

Не используйте номера, которые уже есть у upstream: локальный клон получает и теги upstream. По той же причине не делайте `git push --tags`.

Репозиторий раньше назывался `Asofwar/forkop`. GitHub перенаправляет на новое имя ссылки на репозиторий, `git` и API, но не адрес Pages: `https://asofwar.github.io/forkop` больше не отвечает. Не создавайте новый репозиторий с именем `forkop` — перенаправления перестанут работать. В старом локальном клоне: `git remote set-url origin https://github.com/Asofwar/prokop.git`.

</details>

## Происхождение

Prokop — самостоятельный форк со своим именем, пакетами и каналом релизов; он ставится и обновляется только из релизов [Asofwar/prokop](https://github.com/Asofwar/prokop) и не зависит от инфраструктуры upstream.

Линия проекта: [Podkop](https://github.com/itdoginfo/podkop) → Podkop Plus → [Forkop](https://github.com/ushan0v/forkop) (так переименовали Podkop Plus) → [slayer326/forkop](https://github.com/slayer326/forkop) → **Prokop**. Спасибо авторам всех этих проектов, а также авторам форков Forkop, из которых перенесены исправления и функции.
